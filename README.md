# درگاه معلمان سمپاد و API

این پوشه سرویس وب معلمان و API مرکزی را شامل می‌شود. اپ دسکتاپ داده‌های محلی را نگه می‌دارد و با API روی VPS همگام می‌شود. سرور به Node.js 20 یا جدیدتر و MongoDB نیاز دارد.

## راه‌اندازی روی VPS

1. فقط فایل‌های این بسته را روی VPS قرار دهید؛ `.env` محرمانهٔ خودتان را جداگانه روی سرور بسازید. از `.env.example` الگو بگیرید. ZIP عمومی عمداً فایل `.env` ندارد.
2. MongoDB را با احراز هویت فعال کنید. کاربر برنامه را با نقش `readWrite` فقط روی دیتابیس `sampad` بسازید و MongoDB را فقط روی `127.0.0.1:27017` گوش‌به‌زنگ بگذارید. پورت دیتابیس را در فایروال عمومی نکنید.
3. مقادیر `MONGODB_URI`، `PUBLIC_ORIGIN`، `JWT_SECRET`، `ADMIN_NATIONAL_ID`، `ADMIN_PHONE` و `ADMIN_PASSWORD` را در `.env` تنظیم کنید. رمز URI اگر نویسهٔ ویژه دارد باید URL-encode شود. برای ساخت کلید نشست قوی می‌توانید روی سرور اجرا کنید: `openssl rand -base64 64`.
4. مطمئن شوید `NODE_ENV=production`، `COOKIE_SECURE=true` و `TRUST_PROXY=1` با یک reverse proxy مورد اعتماد مثل Nginx تنظیم شده‌اند. گواهی TLS برای دامنه الزامی است.
5. وابستگی‌های production را نصب کنید: `npm ci --omit=dev`.
6. مدیر اولیه را فقط یک بار بسازید: `npm run seed:admin`. اسکریپت رمز کوتاه، شناسهٔ نمونه و شمارهٔ خالی/نمونه را رد می‌کند. پس از ساخت، `ADMIN_PASSWORD` را از `.env` پاک کنید. این دستور پشت ترمینال VPS اجرا می‌شود و API عمومی برای ساخت مدیر ندارد.
7. سرویس را با `npm start` اجرا کنید. API به‌طور پیش‌فرض فقط روی `127.0.0.1:8080` گوش می‌دهد. پیکربندی Nginx و systemd نمونه در پوشهٔ `deploy` است؛ گواهی TLS و مسیر دامنه را مطابق VPS خودتان تنظیم کنید.
8. مدیر در سایت پنل ورود ندارد و کار مدیریتی را فقط از اپ دسکتاپ انجام می‌دهد. در اپ، آدرس HTTPS و حساب مدیر را در بخش «سایت» یک‌بار وصل کنید، کد امنیتی شش‌رقمی را تنظیم و همگام‌سازی اولیه را اجرا کنید. اپ رمز اتصال را رمزگذاری‌شده در ویندوز نگه می‌دارد، هنگام اجرا همگام‌سازی را شروع می‌کند و نشست را پس از انقضا خودکار تازه می‌کند. معلم‌ها از مسیر `/teachers` با کد امنیتی مدرسه ثبت‌نام می‌کنند و حسابشان خودکار فعال می‌شود.

کد شش‌رقمی فقط امکان ثبت‌نام در مدرسه را باز می‌کند؛ رمز عبور مستقل هر معلم همچنان لازم است. برای ورود مدیر از کد ملی و رمز حساب استفاده می‌شود.

## قابلیت‌ها و دسترسی‌ها

معلم می‌تواند پروفایل و رمز خودش را تغییر دهد، اما کد ملی و نقش خود را تغییر نمی‌دهد. فهرست دانش‌آموزان، کلاس و درس در API کنترل می‌شود و معلم فقط نمرهٔ درس‌های اختصاص‌یافته به خودش را می‌خواند یا ثبت می‌کند. تغییر نمره با نام ثبت‌کننده، زمان، مقدار قبل/بعد و نتیجه در سابقه ذخیره می‌شود. ورود وب فقط برای معلم است؛ مدیر حساب‌ها، دسترسی کلاس/درس، کد امنیتی، همگام‌سازی و تعارض‌ها را از اپ دسکتاپ مدیریت می‌کند.

کد نمرهٔ خالی یعنی درس در کارنامه وارد نشود. نمره بین صفر تا ۲۰ است؛ `-1` غیبت موجه و خارج از معدل است و `-2` غیبت غیرموجه با صفر محاسبه می‌شود. رکورد یک دانش‌آموز برای سال یا موضوع متفاوت مجاز است؛ عنوان‌های مشابه با تفاوت فاصله و حروف عربی/فارسی نرمال می‌شوند تا رکورد تکراری همان آزمون ساخته نشود.

## امنیت و نگه‌داری

رمزها با Argon2id هش می‌شوند؛ کوکی نشست HttpOnly، SameSite و در production حتماً Secure است؛ API محدودیت نرخ، اعتبارسنجی ورودی، کنترل نقش/مجوز و گزارش ممیزی دارد. در production نشانی `PUBLIC_ORIGIN` باید HTTPS باشد و `TRUST_PROXY` فقط proxy واقعی جلوی اپ را بشناسد. هیچ رمز، کد امنیتی خام یا کوکی نشست را وارد ZIP، Git یا پشتیبان قابل اشتراک نکنید.

برای پایگاه‌داده، پشتیبان رمزگذاری‌شدهٔ روزانه از `mongodump` تهیه کنید؛ دسترسی dump را محدود و بازیابی را دوره‌ای در محیط آزمایشی امتحان کنید. دادهٔ دانش‌آموز را در لاگ یا ابزار مانیتورینگ عمومی ثبت نکنید. قبل از مهاجرت schema یا ارتقای MongoDB از پشتیبان قابل‌بازیابی اطمینان بگیرید.

## همگام‌سازی

پس از اتصال یک‌باره، اپ در شروع و هر دقیقه همگام‌سازی می‌کند؛ هنگام بازگشت اپ به پنجرهٔ فعال هم اتصال را بررسی می‌کند. ورود مدیر در ویندوز رمزگذاری می‌شود و با انقضای نشست بی‌درخواست ورود دوباره تمدید می‌شود. داده‌ها صفحه‌بندی/بسته‌بندی می‌شوند؛ برای رکوردهای هم‌زمان، تغییر خودکار روی تغییر دیگر نوشته نمی‌شود و تعارض برای بررسی مدیر ثبت می‌شود. حذف با tombstone به سمت مقابل می‌رود و جلوی زنده‌شدن دوبارهٔ رکورد حذف‌شده را می‌گیرد. حل تعارض از اپ مدیر با انتخاب نسخهٔ محلی یا سایت انجام می‌شود.

اتصال واقعی به VPS در این workspace آزمایش نشده است؛ پیش از ورود دادهٔ واقعی، دامنه و TLS، اتصال MongoDB، پشتیبان/بازیابی، حساب مدیر و همگام‌سازی دوطرفه را روی VPS خودتان آزمایش کنید.

## تست

با وابستگی‌های توسعه نصب‌شده، `npm test` تست API را با MongoDB موقت اجرا می‌کند. اولین اجرا ممکن است باینری تست MongoDB را دانلود کند. تست منطق همگام‌سازی محلی در ریشه پروژه با `node test/sync-core.test.js` اجرا می‌شود.
